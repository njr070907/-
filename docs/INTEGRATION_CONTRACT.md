# 两天演示版集成契约

本文件由 1 号维护。它定义本轮演示版唯一需要跑通的流程、模块边界和合入条件。任何未列出的功能均不进入本轮范围。

## 1. 演示目标

演示者从一条手动粘贴的通知开始，依次完成：

```text
添加通知 -> 提取并编辑字段 -> 保存版本 -> 关联已有事项 -> 查看版本差异 -> 查看本周待办 -> 搜索并回看原文
```

通知来源仅限手动复制或导入的演示数据。本轮不自动登录或抓取公文通，不读取微信群，不处理附件、支付、账号体系或消息推送。

## 2. 数据规则

### Notice

每一条原始通知是一条 `Notice`，`raw_text` 永远保留原文，不被解析结果覆盖。

- `id`：通知版本唯一标识。
- `matter_id`：可为空；确认同一事项后才填写。
- `parse_status`：`raw`、`review_required`、`confirmed` 三选一。
- `extracted_json`：解析结果；未知字段必须为 `null` 或空数组。
- `published_at`：只有原文明确给出时才能填写。

### Matter

`Matter` 代表一件持续办理的校园事务，例如“某学期奖学金材料提交”。一个事项可以有多条通知版本。

- 不同发布方的截止时间不必互相覆盖。
- 仅在用户选择“关联已有事项”或新建事项时，通知才写入 `matter_id`。

### Task

`Task` 表示事项中的一个办理环节，例如“班委收齐材料”“学院提交材料”“学校最终截止”。

- `stage` 必填，用于解释不同截止时间。
- `deadline` 不明确时为 `null`，不能进入本周待办。
- 只有 `confirmed` 的任务才可显示在本周待办。

## 3. 提取协议

4 号提供的提取模块必须返回以下结构。它可以使用模型或规则，但不得猜测原文未出现的信息。

```json
{
  "matter_name": "",
  "audience": [],
  "stage": "",
  "deadline": null,
  "submit_channel": "",
  "materials": [],
  "explicit_change": "",
  "confidence": 0,
  "evidence": []
}
```

- `evidence` 中每一项都必须能定位到原文片段。
- 日期没有年份、时间或指代不清时，保留原文提示并让用户确认。
- 版本差异由程序直接比较 `deadline`、`audience`、`submit_channel`、`materials`；提取模块只生成面向用户的说明文字。

## 4. 模块边界

| 成员 | 分支 | 允许改动 | 交付给 1 号的内容 |
| --- | --- | --- | --- |
| 1 号 | `chore/integration-contract` | 文档、集成配置、演示验收 | 可运行主分支、验收记录 |
| 2 号 | `feature/ui-flow` | `frontend/src/` 页面与样式 | 添加、详情、待办、搜索界面 |
| 3 号 | `feature/matter-task-model` | `backend/app/models.py`、schemas、API、测试 | Matter、Task、关联 API |
| 4 号 | `feature/notice-processing` | 解析与差异服务、相应测试 | 固定 JSON 提取与差异说明 |
| 5 号 | `data/demo-notices` 或 `test/demo-flow` | `data/raw/`、测试、演示材料 | 脱敏通知、回归清单、录屏脚本 |

2 号不直接改后端模型；3 号不直接重写前端；4 号不在解析模块中写数据库；5 号不修改他人通知。发生接口变化时先在 PR 中说明，再由 1 号确认。

## 5. 合入顺序

1. 3 号的 Matter、Task 结构和 API。
2. 4 号的提取和字段差异服务。
3. 2 号的页面接入。
4. 5 号的演示数据与回归测试。

每次合入前，1 号至少检查该 PR 的分支、改动范围、测试说明及与演示数据的兼容性。`main` 不能直接开发或强制推送。

## 6. 最终验收

演示版通过以下八项才可用于答辩：

1. 能粘贴并保存一条通知。
2. 能显示字段提取结果，用户能编辑并确认。
3. 原文缺失的信息不会被补造。
4. 两条通知能手动关联到同一事项。
5. 能显示日期、对象、入口、材料的变化。
6. 本周待办只显示时间明确且已确认的任务。
7. 能搜索通知并回看完整原文。
8. 在手机宽度下可完成上述流程。

## 7. 运行基线

当前仓库已具备 Notice 的 JSON -> SQLite -> FastAPI -> React 链路，但尚未验证本机依赖安装。开始功能开发前，1 号需要记录并解决前端依赖和后端测试环境问题；在此之前，其他成员可完成不依赖运行环境的代码与数据准备。
