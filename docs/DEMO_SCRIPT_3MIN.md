# 三分钟答辩演示脚本

本脚本只使用本地复位后的脱敏演示数据或下列两段脱敏文本。演示前先按 [演示环境启动与安全复位手册](DEMO_RUNBOOK.md) 启动前后端；不要展示真实姓名、学号、微信群或学校平台登录页。

## 开场前准备

1. 执行 `./scripts/Reset-Demo.ps1 -ResetDemo`，再启动后端和前端。
2. 浏览器打开 `http://localhost:5173`，停留在“添加通知”。
3. 把以下两段文字分别放在两个记事本窗口，录制时复制粘贴：

**第一版**

```text
关于创新项目材料申报的通知

适用对象：电子信息学院大一学生
办理阶段：学生提交
提交材料：申请表、项目简介
截止时间：2026年9月22日18:30
提交方式：通过学生事务系统提交。
```

**更新版**

```text
关于创新项目材料申报的更新通知

适用对象：电子信息学院大一、大二学生
办理阶段：学生提交
提交材料：申请表、项目简介、承诺书
截止时间：2026年9月23日20:00
提交方式：通过学院材料平台提交。
适用对象调整为大一、大二学生，截止时间延后，提交入口和材料要求均有调整。
```

## 录制路线（约 3 分钟）

| 时间 | 页面操作 | 说的话 |
| --- | --- | --- |
| 0:00–0:20 | 停在“添加通知”。 | “同学们常在网站和群消息里反复找通知，也容易遇到同一件事的新旧通知时间不一致。校事清先把通知原文保存下来，再由用户确认关键信息。” |
| 0:20–0:45 | 粘贴第一版文字，填标题和来源，点“保存并提取”。 | “这里不登录学校系统，也不自动抓取群消息。我们先处理用户主动粘贴的内容，保留原文作为依据。” |
| 0:45–1:10 | 在核对页依次指向对象、截止时间、入口、材料，展开一项“查看原文依据”。 | “系统把对象、阶段、截止时间、入口和材料整理成草稿。每个字段都要对照原文人工确认，缺失信息不会被补造。” |
| 1:10–1:25 | 新建事项，勾选创建待办，点“确认并保存”。 | “确认后，第一版通知进入一个事项，同时生成明确截止时间的待办。” |
| 1:25–1:45 | 添加更新版，提取后选择“关联已有事项”，选择刚创建的事项，确认保存。 | “当同一件事出现更新通知，用户手动把它归到原事项，不让不同发布方的消息彼此覆盖。” |
| 1:45–2:15 | 在事项详情选择两版，点“开始对比”。 | “系统只比较真正影响行动的字段。这里可以看到截止时间、适用对象、提交入口和材料要求都发生了变化。” |
| 2:15–2:35 | 进入“我的本周”，勾选一个任务再取消。 | “本周页只展示已经确认且日期明确的任务。完成后记录仍保留，也可以取消完成。” |
| 2:35–2:50 | 进入“搜索”，搜索“创新项目”，打开一条通知原文。 | “当同学忘记细节时，可以搜索并回到原文，而不是只相信系统摘要。” |
| 2:50–3:00 | 回到事项或搜索页，停在清晰状态。 | “现在的 MVP 聚焦人工粘贴、可核对的提取和版本变化提醒。下一步会用班级试用反馈验证真实需求。” |

## 录制验收

- [ ] 时长 2 分 40 秒至 3 分 20 秒。
- [ ] 视频中出现添加、确认、同一事项归并、版本对比、本周待办、搜索和原文回看。
- [ ] 展示一次“查看原文依据”。
- [ ] 不出现个人信息、密码、Token、真实校内通知或校园网登录页。
- [ ] 录制完成后播放一次，确认文字、鼠标和声音清楚。
- [ ] 视频保存到 `docs/videos/`，文件名使用 `issue-6-full-demo.mp4`，并在 Issue #6 留下文件位置与录制日期。
