## 缺陷与修复

### #23 P1：返回修改原文后再次保存会生成重复通知

修复前复现：

1. 保存并提取一条通知。
2. 点击“返回修改原文”。
3. 修改正文后再次保存并提取。
4. `/api/notices` 中出现两个标题相同、状态为 `review_required` 的通知。

修复前证据：通知数量从 7 增至 9，重复记录 ID 分别为 `notice_4badb3bfdd8c42edb19ce604b77ef7f4` 与 `notice_16ee3fd65e8749a9833f93123f2c4e62`。

修复内容：

- 新增 `PATCH /api/notices/{notice_id}`，只更新未确认草稿，并清除旧提取结果。
- 前端保存首次草稿 ID；返回编辑后更新同一草稿，再重新提取。
- 增加后端 API 与前端交互回归测试。

修复后浏览器证据：独立复位后通知总数从 7 增至 8；标题为“返回编辑回归测试”的记录只有 1 条，ID 保持不变，正文为修改后的内容。

### #19 P0：旧 SQLite 数据库升级失败

- 主线已修复。
- `test_legacy_sqlite_database_is_backed_up_and_upgraded` 与路径保护测试均通过。

### #21 P1：网络不可用时显示英文错误

- 主线已修复。
- 浏览器断开后端后显示“保存或提取失败，请稍后重试。请检查网络连接或稍后重试。”，原文仍保留。
